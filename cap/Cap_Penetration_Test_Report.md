## 1. Executive Summary

An authorized black-box penetration test was performed against the host `10.10.10.245`, which exposes an SSH service, an FTP service, and a custom Python web application branded "Security Dashboard."

The assessment identified a complete compromise path that takes an **unauthenticated external attacker to full root-level control** of the host. The entry point was an **Insecure Direct Object Reference (IDOR)** in the dashboard's packet-capture feature, which allowed any visitor to download network captures belonging to other users. One such capture contained **cleartext FTP credentials**. Those credentials were **reused for SSH**, granting an interactive foothold. Finally, a **dangerous Linux capability (`cap_setuid`) assigned to the Python interpreter** allowed trivial privilege escalation to `root`.

Individually the issues range from medium to high severity; **chained, they constitute a critical risk**, as no authentication, phishing, or user interaction is required at any stage.

## 4. Detailed Findings

---

### CAP-01 — Insecure Direct Object Reference (IDOR) in `/data/<id>`

| | |
|---|---|
| **Severity** | High |
| **CVSS v3.1** | 7.5 — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` |
| **CWE** | CWE-639: Authorization Bypass Through User-Controlled Key |
| **Affected** | `http://10.10.10.245/data/<id>` |

**Description.** The "Security Snapshot" feature generates a packet capture per request and exposes the result at `/data/<id>`, where `<id>` is a sequential integer. The application performs **no ownership or authorization check** on the identifier. Any visitor can enumerate IDs and retrieve captures generated by other users or by the system itself.

**Evidence.** Requesting `/data/0` returns a capture that does not belong to the current session, with no access-control error.
`[SCREENSHOT: screenshots/05-data-0-idor.png]`

**Impact.** Unauthorized disclosure of arbitrary stored network captures, which may contain credentials, session tokens, or other sensitive data (see CAP-02).

**Remediation.**
- Enforce server-side authorization: a capture may only be read by the authenticated principal that created it.
- Use unguessable identifiers (UUIDv4) as defense-in-depth.
- Return `403/404` for unauthorized or non-existent IDs without distinguishing them.

### CAP-02 — Sensitive data exposure: cleartext credentials in downloadable capture

| | |
|---|---|
| **Severity** | High |
| **CVSS v3.1** | 7.5 — `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` |
| **CWE** | CWE-312: Cleartext Storage of Sensitive Information |
| **Affected** | `/data/0/download` (PCAP artifact) |

**Description.** The capture retrievable via CAP-01 contained a full FTP authentication exchange in plaintext. Extracting the stream yielded valid credentials for the user `nathan`.

**Evidence.**
```bash
tshark -r 0.pcap -Y 'ftp' -T fields -e ftp.request.command -e ftp.request.arg
USER   nathan
PASS   ********   (recovered in cleartext)
```
`[SCREENSHOT: screenshots/07-wireshark-ftp-creds.png]`

**Impact.** Directly provides valid account credentials to an unauthenticated attacker, enabling authenticated access to the host (see CAP-04).

**Remediation.**
- Never retain captures containing credentials; restrict downloads to the owner (CAP-01).
- Eliminate cleartext authentication on monitored services (CAP-05).
- Rotate any credentials known to have traversed the network in plaintext.

### CAP-03 — `cap_setuid` on `/usr/bin/python3.8` → privilege escalation to root

| | |
|---|---|
| **Severity** | Critical |
| **CVSS v3.1** | 8.8 — `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H` |
| **CWE** | CWE-250: Execution with Unnecessary Privileges |
| **Affected** | `/usr/bin/python3.8` |

**Description.** The Python 3.8 binary has the `cap_setuid` file capability set. This allows any user who can execute it to change the process UID to 0 and obtain a root shell, without `sudo` or an SUID binary.

**Evidence.**
```bash
getcap -r / 2>/dev/null
/usr/bin/python3.8 = cap_setuid+eip

/usr/bin/python3.8 -c 'import os; os.setuid(0); os.system("/bin/bash")'
# id -> uid=0(root)
```
`[SCREENSHOT: screenshots/09-getcap.png]` · `[SCREENSHOT: screenshots/10-root-flag.png]`

**Impact.** Complete local privilege escalation. Any foothold on the host becomes full root control.

**Remediation.**
- Remove the capability: `sudo setcap -r /usr/bin/python3.8`.
- Never assign `cap_setuid` (or similar) to general-purpose interpreters.
- Audit capabilities regularly: `getcap -r / 2>/dev/null`.

### CAP-04 — Credential reuse across FTP and SSH

| | |
|---|---|
| **Severity** | Medium |
| **CVSS v3.1** | 6.5 |
| **CWE** | CWE-308 / weak credential hygiene |

**Description.** The FTP credentials recovered in CAP-02 authenticated successfully to SSH, providing an interactive shell as `nathan`.

**Evidence.** `ssh nathan@10.10.10.245` accepted the FTP password. `[SCREENSHOT: screenshots/08-user-flag.png]`

**Impact.** A single leaked secret escalated from file transfer to full interactive command execution.

**Remediation.** Enforce unique credentials per service; prefer SSH key authentication; disable password SSH where possible.

---

### CAP-05 — Cleartext protocol in use (FTP / vsftpd 3.0.3)

| | |
|---|---|
| **Severity** | Medium |
| **CVSS v3.1** | 5.3 |
| **CWE** | CWE-319: Cleartext Transmission of Sensitive Information |

**Description.** FTP transmits credentials and data without encryption, making them trivially recoverable from any captured traffic.

**Remediation.** Replace FTP with SFTP (over SSH) or FTPS; decommission vsftpd if unused.

---

### CAP-06 — Verbose service / version disclosure

| | |
|---|---|
| **Severity** | Low / Informational |
| **CVSS v3.1** | 3.1 |
| **CWE** | CWE-200: Information Exposure |

**Description.** Service banners disclose exact versions (`vsftpd 3.0.3`, `OpenSSH 8.2p1`, `gunicorn`), aiding an attacker in matching known vulnerabilities.

**Remediation.** Where supported, suppress or genericize version banners; keep services patched so version disclosure is low-value.

## 5. Attack Narrative (chained)

```
Unauthenticated web visitor
   │  CAP-01  walk /data/<id> back to 0  (IDOR)
   ▼
Download foreign PCAP
   │  CAP-02  extract cleartext FTP creds (nathan)
   ▼
Authenticate to FTP, then SSH
   │  CAP-04/05  password reuse over cleartext protocol
   ▼
Interactive shell as nathan (user.txt)
   │  CAP-03  python3.8 cap_setuid → os.setuid(0)
   ▼
root (root.txt)  — full host compromise
```

**Time to full compromise:** minutes, no user interaction, no authentication at entry.

---

## 6. Strategic Recommendations

1. **Fix the privilege-escalation primitive first** (CAP-03) — it is the highest-impact, single-command fix.
2. **Close the IDOR and stop exposing captures** (CAP-01/02) — removes the unauthenticated entry point.
3. **Retire cleartext protocols and enforce credential hygiene** (CAP-04/05).
4. Introduce a recurring capability/SUID audit and an authorization test suite into CI.
